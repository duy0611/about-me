# About-me — Duy Nguyen's resume site

Static resume, generated from YAML, hosted on GitHub Pages, printable as PDF, tailorable per job type.

**Live:** https://duy0611.github.io/about-me/

Variants:

- Default — https://duy0611.github.io/about-me/
- Site Reliability — https://duy0611.github.io/about-me/?variant=sre
- Platform Engineering — https://duy0611.github.io/about-me/?variant=platform
- Backend Development — https://duy0611.github.io/about-me/?variant=backend
- Debug mode — https://duy0611.github.io/about-me/?debug=true

## How it works

- `data/base.yaml` is the canonical resume.
- `data/overlays/*.yaml` are per-role overlays — small YAML files that override
  parts of the base (typically `summary` and `competencies`). They're deep-merged
  onto a fresh clone of the base at build time.
- `build.js` renders one `index.html` containing the default variant statically,
  plus an embedded JSON blob of every variant's pre-rendered sections.
- `src/switcher.js` reads `?variant=…` from the URL and swaps the right sections
  in. The page still works with JavaScript disabled — it just shows the default.
- Print styles (`@media print` in `src/styles.css`) mean `Cmd/Ctrl+P → Save as
  PDF` gives you a clean printable resume.

## Local development

```bash
npm install
npm run build      # writes dist/index.html + assets
npm run dev        # build + serve at http://localhost:5173
npm run pdf        # build + render dist/resume{,-<variant>}.pdf via Puppeteer
```

Open `http://localhost:5173/` (default) or `http://localhost:5173/?variant=sre`.

Downloadable PDFs after `npm run pdf` or after CI deploy:

- `resume.pdf`
- `resume-sre.pdf`, `resume-platform.pdf`, `resume-cloud.pdf`, `resume-backend.pdf`

They live next to `index.html` and are hyperlinked from the header "Download PDF" button (link updates as you switch variants).

## Adding a new job-type variant

1. Copy an existing overlay, e.g. `cp data/overlays/sre.yaml data/overlays/data.yaml`.
2. Edit `meta.headline`, `summary`, and `competencies` for the new target role.
   Anything you don't override (experience, education, certifications, languages)
   falls through to `data/base.yaml`.
3. Add the option to the picker in `src/template.hbs`:

   ```html
   <option value="data">Data Engineering</option>
   ```

4. `npm run build`, verify locally, push. The URL `?variant=data` will work.

## PDF generation

The site ships pre-rendered PDFs — one per variant — generated by Puppeteer
(headless Chrome) rendering the screen HTML at 1024px viewport and paginating
to A4. This produces a pixel-accurate copy of the two-column screen layout,
including the sidebar tint and pill-styled skills.

- Locally: `npm run pdf` → PDFs land in `dist/`.
- CI: the `Deploy` workflow runs `npm run pdf` before uploading the Pages
  artifact, so every push to `main` republishes fresh PDFs alongside the site.

The header's **Download PDF** button links to the current variant's PDF and
rewires itself when the variant dropdown changes.

Browser `Cmd/Ctrl+P` also works as a fallback but uses the print stylesheet
(single-column, compact) — the pre-rendered PDFs are the canonical output.

## Deployment

GitHub Actions (`.github/workflows/deploy.yml`) builds and deploys to GitHub Pages
on every push to `main`. First-time setup:

1. Repo **Settings → Pages → Source: GitHub Actions** (one-time).
2. Push to `main`. The workflow builds and publishes.
